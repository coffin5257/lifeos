# LifeOS

**中文** · [English](README.en.md)

让 Codex 或 Claude Code 在不同对话里持续理解你的目标、关系、项目和决定。内容保存在你自己的文件夹里。

## 现在试一下

1. 准备一个空文件夹，或打开你已有的个人知识目录。
2. 在这个目录中启动 Codex 或 Claude Code。
3. 把下面这句话发给它：

```text
请完整读取 https://raw.githubusercontent.com/coffin5257/lifeos/main/START.md，
按当前版本直接在当前文件夹初始化我的 LifeOS。不要先问我问题，不要虚构个人内容，
不要覆盖已有文件，也不要默认使用 Git。
```

Agent 会建立一套可读的 Markdown 结构。完成后，你可以直接说：

```text
帮我整理现在最重要的三件事，只保留仍然有效的下一步。
```

或者：

```text
分析这次会议。保留原始记录，把决定和待办写回相关项目。
```

```text
我在考虑换工作。把事实、我的判断、可选方案和最终决定分开记录。
```

你不需要 clone 这个仓库，也不需要把个人内容上传到 GitHub。

## 它解决什么问题

普通 AI 对话很容易失去上下文。你换一个会话，就要重新介绍自己；旧计划和新状态混在一起；结论留下了，来源却找不到。

LifeOS 给 Agent 一个长期可读的本地上下文：

- `me/priorities.md` 告诉它你现在最重要的事；
- 人物和项目入口保存当前状态，而不是堆满全部历史；
- 原始聊天、会议和文档保留下来，结论可以回到来源核实；
- 已结束的工作进入 archive，不再被当作当前待办；
- Codex 和 Claude Code 可以读同一套文件继续工作。

它适合已经在使用 Coding Agent，并希望 AI 逐渐了解自己的人。它目前不是带 GUI 的应用，也不会自动同步你的所有账号。

## 几条简单规则

**先看现在。** Agent 先读当前优先级和相关人物、项目，再按需查原始资料。

**保留来源。** 摘要、分析和知识不能覆盖聊天、会议或文档原件。

**历史会降权。** 旧内容仍可追溯，但默认不参与今天的判断。

**用到再增加。** 模板、Skill、Connector 和自动化只有在真实工作反复需要时才加入。

这些规则来自一套持续使用的个人系统。这个公开仓库只保留通用协议，不包含其中的个人资料。

## 文件放在哪里

初始化后，LifeOS 会提供以下语义位置。已有目录会被映射和补齐，不会为了符合模板而重排。

<details>
<summary>查看默认结构</summary>

```text
me/          自己、原则、优先级和重大决定
people/      人物与关系
project/     有目标和结束条件的项目
area/        健康、财务、职业等长期领域
source/      外部原始资料
minutes/     会议录音、转写和纪要
discuss/     针对具体问题的分析
knowledge/   从来源编译出的主题知识
inbox/       尚未判断归属的捕获
outputs/     值得长期保留的成品
templates/   已经反复使用的结构
archive/     不再代表当前状态的历史内容
```

`.lifeos/` 保存这套系统的路径映射、核心规则、Connector 状态和演进记录。

</details>

## 数据与工具

LifeOS 是本地文件，不绑定数据库或云服务。你可以自行选择普通文件夹、iCloud、Dropbox、NAS 或 Git。

Agent 需要处理下载、转换、代码、缓存或日志时，应在 LifeOS 之外使用临时工作目录，只把值得长期保留的来源和结果写回来。

Lark、Slack、Notion、Figma、邮箱等 Connector 按任务启用。授权前先确认账号和读取范围；密码、token 和设备码不写入 LifeOS。

## 这个仓库

这是一个可以使用的早期种子，不是完整产品。如果一次真实使用没有得到你需要的结果，请[提交 Issue](https://github.com/coffin5257/lifeos/issues/new)，说明你想完成什么、哪里卡住了，以及你希望 Agent 保留什么工作方式。不要附带私密资料或凭证。
