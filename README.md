# LifeOS

**中文** · [English](README.en.md)

**让个人拥有自己的长期 AI 上下文。**

LifeOS 是给 Codex、Claude Code 等 Agent 使用的个人上下文系统。它记录你现在重视什么，哪些决定已经做出，哪些信息已经过期，以及结论来自哪里。内容保存在你自己的文件夹里，可以被人阅读，也可以被不同 Agent 继续使用。

```text
无论此前的对话或记忆如何，请完整读取 https://raw.githubusercontent.com/coffin5257/lifeos/main/START.md，
按当前版本直接在当前文件夹初始化我的 LifeOS。不要先问我问题，不要虚构个人内容，
不要覆盖已有文件，也不要默认使用 Git。
```

## 使命

今天，AI 对一个人的理解通常散落在聊天记录、产品 Memory 和不可见的模型状态里。换一个会话、模型或工具，关系就要重新开始；它记住了什么、依据是什么、是否已经过期，个人也很难掌握。

LifeOS 希望把这份长期上下文交还给个人：

- 由本人保存和修改，不被某个平台锁定；
- 能被不同 Agent 读取，不随工具切换消失；
- 保留来源和时间边界，不把记忆当成永远正确的事实；
- 随真实生活持续更新，而不是一次导入后逐渐陈旧。

最终要建立的不是一份更完整的个人档案，而是一套能陪伴多年、帮助人做判断和行动、同时不取代本人决定权的基础设施。

## 当聊天记录不再够用

当你开始让 AI 分析职业选择、准备 1:1、推进项目、消化会议或整理家庭财务时，“它记得我说过什么”已经不够了。

它还需要知道：

- 哪些材料是原始事实，哪些是后来的判断；
- 哪份计划仍然有效，哪些待办已经结束；
- 一次讨论有没有真正变成决定；
- 当前问题和哪些人物、项目、原则有关；
- 下一步完成到什么程度才算有证据。

LifeOS 承担的就是这份工作：当你把越来越重要的事情交给 AI 时，它维护一套持续更新、能够核实的个人上下文，让你不必反复重建背景，也不会让旧信息替今天做决定。

## 一套真实的 LifeOS 做过什么

这个仓库提炼自一套持续使用的个人系统。下面不是设想中的场景，而是它已经承担过的工作。

### 保存一项职业决定如何发生

系统记录过一次持续跟踪的职业去留判断。最初的框架是观察负面信号，后来被新证据修正为比较机会成本；实际完成工作切换后，旧的观察窗口被关闭，而不是继续以“当前计划”的形式残留。

留下来的不只是“换了工作”这个结果，还有当时的事实、选项、判断变化、执行结果和复查条件。

### 在上下文切换后保护现在

换到新的工作环境后，前公司的项目、人物判断和行动项被保留为历史，但不再参与日常建议。新公司的优先级、协作关系和项目状态重新成为默认入口。

这让 Agent 能记住过去，又不会把过去误当成现在。

### 把大量工作记录变成可用判断

在一次工作上下文刷新中，系统消化了数万条消息和数十份会议记录，把它们整理成当前优先级、核心合作网络、项目决定和待确认事项。会议中的探索、偏好、决定和资源承诺被分开记录。

结果不是一份更长的会议摘要，而是下一次工作时可以直接使用的当前状态。

### 让家庭财务成为可校准的政策

系统把资产快照、贷款条件、必要支出和收入假设分开，形成家庭投资政策和逐月路径。未来奖金没有被写成已有资产，历史快照也不会冒充实时余额；每月只需用实际数据重新校准。

它保存的是决策方法和安全边界，不是一次性的投资建议。

### 研究人和 Agent 如何可靠协作

系统曾盘点两个月内 2,119 个 Coding Agent 主会话，并深读其中 21 个复杂案例。最终发现，长任务最常见的问题不是 Agent 不会写代码，而是它会混淆“实现了”“本地测试通过”“已经部署”和“用户真正验收”。

这些发现后来进入 LifeOS 的完成状态、证据、授权和真实验收规则。系统不仅保存结果，也会修正人与 AI 之后如何工作。

公开仓库不包含这些案例的个人资料或内部原文，只保留从真实使用中提炼出的通用协议。

## 它和常见工具的区别

| 工具 | 擅长什么 | 长期协作时缺什么 |
|---|---|---|
| AI 聊天记录与 Memory | 记住对话和偏好 | 很难维护来源、时效、决定状态和完整上下文 |
| Notion、Obsidian 和文档目录 | 保存与检索资料 | 资料不一定会自动成为当前状态和下一步 |
| 任务管理器 | 跟踪待办和截止日期 | 行动与人物、项目、原始证据和判断过程分离 |
| LifeOS | 连接来源、当前状态、判断、决定、行动和历史 | 需要在真实使用中持续维护，没有“导入一次就完成” |

LifeOS 不替代这些工具。它给 Agent 一套跨工具的语义，让不同来源能够进入同一个判断过程。

## 它如何保持可信

**当前状态优先。** Agent 先读你现在的优先级和相关人物、项目，再按需打开会议、聊天和文档。

**原始材料保留。** 摘要、分析和知识不会覆盖原件。重要结论可以回到来源核实。

**判断有时间边界。** 一次谈话不会自动变成稳定的人物结论；带日期的资产和健康信息不会被当成永久事实。

**历史默认降权。** 已结束的项目和待办进入 archive，保留用于追溯，但不继续占据今天的注意力。

**能力从真实摩擦中长出来。** 重复的文档才成为模板，稳定的工作流才成为 Skill，反复搬运的外部信息才值得接 Connector。

## 开始使用

1. 准备一个空文件夹，或打开你已有的个人知识目录。
2. 在这个目录中启动 Codex 或 Claude Code。
3. 复制 README 开头的 Prompt。

Agent 会先建立完整、可导航的 Markdown 基础框架，不要求填写问卷，也不会为了展示效果虚构项目。已有目录会被兼容映射，不会为了符合模板而重排。

初始化后，从一件真实的事开始：

```text
帮我整理现在最重要的三件事，只保留仍然有效的下一步。
```

```text
分析这次会议。保留原始记录，把决定和待办写回相关项目。
```

```text
我正在考虑一个重要选择。把事实、我的判断、选项和最终决定分开记录。
```

你不需要 clone 这个仓库，也不需要把个人内容上传到 GitHub。

## 数据与边界

LifeOS 是本地文件，不绑定数据库或云服务。你可以选择普通文件夹、iCloud、Dropbox、NAS 或 Git。

下载、转换、代码、缓存和日志放在 LifeOS 之外的临时工作目录，只把值得长期保留的来源和结果写回来。Lark、Slack、Notion、Figma、邮箱等 Connector 按任务启用；密码、token 和设备码不写入 LifeOS。

当前版本是一颗可实际使用的公共种子，不是带 GUI 的完整产品。初始化协议见 [`START.md`](START.md)，Agent 规则和模板见 [`seed/`](seed/)。

如果一次真实使用没有得到你需要的结果，请[提交 Issue](https://github.com/coffin5257/lifeos/issues/new)，说明你想完成什么、哪里卡住了，以及你希望 Agent 保留什么工作方式。不要附带私密资料或凭证。
